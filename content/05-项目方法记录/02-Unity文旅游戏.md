# Unity 文旅游戏

## 项目抽象

一个 2D 园林探索与小游戏集合，包含开场视频、菜单入口、地图交互、视频弹窗、场景过渡、平台跑酷、节奏玩法、角色动画和持久化恢复状态。

## 你的工作思路

### 1. 优先沿用现有项目结构

在已有场景、预制体、控制器和美术上增量修改。新功能尽量复用现有 Canvas、场景切换、PlayerPrefs 和输入逻辑；若目标场景缺失，先确认真实 Build Settings，而不是凭按钮名称猜。

### 2. 把功能拆成可独立验收的状态机

例如视频弹窗要验证首次打开、关闭、再次打开；场景过渡要验证加载、完成暂停、渐黑、激活、渐显；节奏游戏要验证 Tap/Hold、提前释放、无输入、结果清理。

### 3. 参数调优必须建立测量点

游戏手感、角色落脚、判定线、进度条等不能只凭肉眼。你逐渐采用逻辑锚点、碰撞体底部、Sprite tight mesh 最低点、DSP 时间、判定窗口等可测量量。

### 4. 验收从真实入口开始

不是直接加载目标场景或传送状态，而是从菜单入口、碰撞提示、按键或按钮进入，再完整走到返回主场景。测试捷径只能用于诊断，不能替代最终验收。

## 主要坑

### 逻辑脚底与视觉脚底不一致

碰撞体已经贴地，但不同动画帧的最低不透明像素/网格高度不同，导致角色看起来悬浮。最终需要逐帧计算视觉最低点，把渲染对象相对逻辑脚点动态校正。

### 障碍物与可站立面混在一起

统一碰撞层会让装饰物、石头、横梁被当成地面。解决方式是把 WalkableSurface 与 RunnerObstacle 分层：平台使用单向顶部碰撞，障碍使用触发器或独立逻辑。

### 视频只能播放一次

只在首次初始化 Prepare/RenderTexture，关闭后没有重置和重新绑定。再次打开需要清理输出、重置时间、重新 Prepare，并在完成回调中启动。

### 场景切换“能跳转”但体验突兀

真正的异步加载进度、进度条动画、完成停留、渐黑与目标场景渐显要形成连续时间线；简单切黑会让体验断裂。

### 节奏玩法使用普通帧时间

音乐判定依赖 DSP 时间更稳定。Hold 的头、体、尾需要明确锚点与生命周期，最终结果只能结算一次，释放宽限与残留视觉要单独验证。

### 测试状态污染

PlayerPrefs、验收开关、临时对象、默认 Play Mode 场景若不恢复，下一次任务会在错误基线开始。

## 可复用验收

- 脚本编译、场景验证、缺失脚本、破损预制体；
- Console 本次新增 Error/Warning；
- 正常路径、重复路径、失败路径；
- 输入边界与设备切换；
- UI 安全区、遮挡、可读性与过渡；
- 物理锚点与渲染像素一致；
- 场景已保存；
- 测试状态清理、默认启动恢复、退出 Play Mode。
