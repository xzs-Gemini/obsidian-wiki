# Obsidian 与 Codex 集成

## 项目抽象

让 Obsidian、第三方对话插件与本地 Codex CLI/应用服务形成可读、可搜、可创建、可修改、可删除的知识库工作链路。

## 你的工作思路

### 1. 分段证明链路

```text
Vault 存在
→ Obsidian 能打开
→ 插件已启用
→ Codex CLI 可执行且已认证
→ 插件 Provider 配置正确
→ App Server 能建会话
→ Vault 读/搜/写通过
→ GUI 文件树与内容可见
→ 删除清理经确认
```

### 2. 功能证明与 GUI 证明分开

后端兼容会话能读写 Vault，说明核心链路可用；但如果 Electron 窗口抓取失败，只能标记 GUI 证据缺失，不能反过来判定整个链路失败。

### 3. 测试文件应最小且可清理

创建专用测试笔记，验证读、搜索、创建、追加、回读。删除属于破坏性操作，动作前确认，并且只删除明确测试对象。

## 主要坑

- Vault 实际只有极少笔记，预设的“搜索五个已有 H1 文件”无法满足；正确做法是准确报告前置条件不足，再使用新建测试样本验证。
- WindowsApps 中的 CLI 路径、短路径或硬链接可能影响第三方插件调用。
- Computer Use 的运行时或 Electron 状态捕获可能失败，但 CLI/App Server 仍然正常。
- 删除测试文件需要单独确认；不能因“测试结束”自动推断用户同意删除。
- 编码和中文路径必须用 UTF-8 回读验证。

## 可复用验收

- 读取、内容搜索、文件创建、精确追加、回读一致；
- GUI 树与编辑区独立确认；
- 中文路径/内容无乱码；
- 只删除测试文件且已确认；
- 测试结束后 Vault 回到原始状态。

本知识库本身就是该方法的一个实践：独立 Vault、中文路径、模板目录、双链检查和隐私抽象。
