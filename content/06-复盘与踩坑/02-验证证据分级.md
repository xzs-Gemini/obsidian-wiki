# 验证证据分级

## 证据等级

| 等级 | 证据 | 能证明什么 | 不能单独证明什么 |
|---|---|---|---|
| E0 | 模型判断/代码阅读 | 可能的逻辑 | 运行结果 |
| E1 | 静态检查/类型/Schema | 结构与类型一致 | 用户流程 |
| E2 | 编译/构建/导出 | 能生成目标产物 | 功能与视觉正确 |
| E3 | 单元/集成测试 | 规定输入下逻辑成立 | 真实应用交互 |
| E4 | 运行时状态/日志/Console | 应用实际执行 | 用户是否看见正确结果 |
| E5 | GUI/截图/渲染 | 可见界面与布局 | 内部数据完整性 |
| E6 | 端到端用户路径 | 从入口到结果可用 | 所有设备/环境都可用 |
| E7 | 真实设备/外部环境 | 目标设备和真实条件可用 | 长期稳定性 |

## 你的默认完成门槛

- 数据/后端：至少 E1 + E3 + E4。
- 普通功能：至少 E1 + E2 + E4 + E6。
- GUI/游戏：至少 E1 + E2 + E4 + E5 + E6。
- XR/移动真机：自动化最多先到 E6；只有设备实测才是 E7。
- 文档/PPT：结构检查 E1 + 文件生成 E2 + 渲染检查 E5。

## 报告写法

```text
已验证：在 Play Mode 中从菜单入口进入，完成交互并返回；Console 无新增错误。
未验证：没有连接目标头显，因此只完成模拟器验证，真机状态为 NOT VERIFIED。
```

避免模糊词：

- “应该可以” → 写成未验证；
- “测试通过” → 列测试名与真实路径；
- “没有问题” → 写检查范围和遗漏范围；
- “已上线” → 给部署地址与可达性证据，否则不要使用。
