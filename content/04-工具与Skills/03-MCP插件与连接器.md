# MCP、插件与连接器

## 三者关系

- **MCP Server**：向 Codex 暴露结构化工具或上下文。
- **Connector/App**：面向某个外部服务的授权连接，通常由 MCP 支撑。
- **Plugin**：可安装的能力包，可同时包含 Skills、MCP、Connector 和界面资源。

## 什么时候用 MCP

- 需要读取/修改专业应用内部结构，例如 Unity 场景、Figma 节点；
- 需要访问私有服务的数据；
- 需要可靠地重复调用同一种操作；
- GUI 点击太脆弱或无法证明内部状态。

## MCP 的标准验收

```text
服务可达 ≠ 工具通道可用 ≠ 目标应用已连接 ≠ 命令执行成功
```

建议依次验证：

1. MCP 服务是否启动；
2. 目标实例是否注册；
3. 读取命令是否返回；
4. 写命令是否得到完成结果；
5. 目标应用状态是否真实变化；
6. 应用日志/Console 是否干净。

## 你踩过的代表性坑

- 服务注册能看到 Unity 实例，但 WebSocket 命令/结果通道已经断开。
- Session ID 重连后变化，旧句柄不能继续使用。
- 某个 API 调用返回成功，但应用仍在编译或尚未保存。
- Connector 有权限不代表用户授权了本次发送、删除或发布。
- 缺少插件时，不应假设它存在；先检查已安装能力，再决定是否安装或给出替代方案。

## 推荐提示词

```text
优先使用【专用 MCP/Connector】完成结构化读取与修改。先验证服务、实例和命令通道；每次写入后从目标应用重新读取状态并做运行验收。不要把“工具调用成功”当作“用户目标已完成”。
```

## Plugin 与 Skill 的选择

- 只有流程：用 Skill。
- 需要服务连接或结构化工具：用 Plugin/MCP。
- 需要一套流程加外部系统：Plugin 中同时包含 Skill 与 Connector。
