# 任务路由表

| 任务 | 首选能力 | 原因 | 不建议首选 |
|---|---|---|---|
| 读写本地代码/Markdown | 文件工具 + Shell + Apply Patch | 精确、可审计、易复现 | Computer Use 点编辑器 |
| 控制 Unity 项目 | Unity MCP | 能读场景、对象、Console、Play Mode | 只靠鼠标点击 Unity |
| 观察桌面 GUI | Computer Use | 能看窗口、点击、输入与验证视觉状态 | 猜测界面状态 |
| 测试本地网页 | 内置 Browser | DOM/页面证据更稳定 | Windows 上用 Computer Use 操作浏览器 |
| 公开资料检索 | Web Search | 可给真实链接与最新信息 | 凭记忆写时效性事实 |
| 私有云数据 | 对应 Connector/MCP | 有授权、结构化、可追踪 | Web Search |
| Word/PPT/PDF/表格 | 对应文档 Skill | 有专门的生成、渲染与验收流程 | 直接手写二进制文件 |
| 图片生成/编辑 | ImageGen/创意 Skill | 能产出视觉资产 | 用脚本假装图像生成 |
| 重复工作流 | Skill | 复用固定流程与模板 | 每次粘贴长提示词 |
| 项目长期规则 | `AGENTS.md` | 每次任务自动读取 | 只写在某个聊天里 |
| 并行的独立子任务 | Subagents | 降低主线程噪声、缩短时间 | 多代理同时改同一文件 |
| 定时检查/提醒 | Automation | 按计划重复执行 | 让普通对话“自己等” |

## 简单判断树

```text
能直接读文件/调用结构化接口吗？
├─ 能 → 优先文件工具、CLI、MCP 或 Connector
└─ 不能 → 是否必须看图形界面？
   ├─ 是 → Computer Use
   └─ 否 → Web/Search/专用 Skill
```

## 你的默认优先级

**结构化能力 > 文件与命令 > 专用 Skill > Browser > Computer Use。**

这不是能力高低排序，而是稳定性、可复现性和审计成本排序。Computer Use 很有用，但最适合完成“必须真实看见或点击”的最后一公里。
