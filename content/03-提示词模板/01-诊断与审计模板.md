# 诊断与审计模板

## 只读根因分析

```text
请对【项目/文件/应用/场景】进行只读诊断，目标是确定【问题】的真实原因。

先读取【AGENTS.md/README/交接/配置/日志】，建立当前基线。
允许：读取文件、运行只读检查、查看日志、复现问题。
禁止：修改文件、安装依赖、删除数据、改变配置、发送或发布内容。

请区分：
1. 可观察症状；
2. 直接原因；
3. 根因；
4. 证据；
5. 最小修复方案；
6. 仍无法确认的事项。

最终只给结论、证据路径和建议，不实施修复。
```

## 代码审计

```text
请审计【模块/PR/目录】，重点检查【数据一致性/状态机/性能/安全/可访问性】。
先画出调用链和数据流，再列发现。
发现按严重度排序，每项给出可复现条件、影响和精确文件位置。
没有证据的问题不要当成缺陷；不要修改代码。
```

## 环境故障

```text
请诊断【工具/服务】无法运行的问题。按“进程 → 端口 → 配置 → 依赖 → 网络 → 日志 → 最小重试”顺序排查。
不要把服务注册成功等同于命令通道可用；不要反复执行可能改变环境的修复命令。
若阻塞来自用户操作、UAC、协议接受或外部服务，停在准确断点并说明下一步。
```
